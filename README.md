# vpn-tunnel

Личный VPN на VPS через **VLESS + REALITY**: клиент sing-box подключается к
Xray, серверные DNS и Mihomo обрабатывают доменные списки и блокируют рекламу.
Большие списки остаются на сервере, на устройства доставляются небольшие JSON.

## Требования

Чистый VPS с Ubuntu 24.04 x86_64, systemd, cgroup v2, публичным IPv4,
Python 3.12, Git и сертификатами CA. Нужны минимум 650 МиБ доступной RAM и
2 ГиБ свободного места на файловой системе каталога проекта.
Входящий **TCP 443** должен быть открыт; установщик не меняет firewall.
Требуется исходящий доступ к источникам списков, GitHub и службам проверки
DNS, HTTPS и STUN.

На устройстве нужен клиент с ядром **sing-box 1.14.2**, поддерживающий импорт
полного JSON, TUN/VPN, VLESS + REALITY, DNS и удалённые правила.
Проверяйте встроенное ядро, а не только версию приложения.

## Установка на VPS

Все серверные команды в этом README выполняются **от root**, в Bash/zsh.
Рекомендуемый каталог — `/root/vpn-tunnel`. При отсутствии пакетов установите их,
затем скачайте проект и запустите установку:

```sh
apt-get update
apt-get install -y git python3 ca-certificates
git clone https://github.com/leskafey/vpn-tunnel.git /root/vpn-tunnel
cd /root/vpn-tunnel
./audit.sh
./install.sh --server-ip IP_НОВОГО_VPS
```

Вместо `IP_НОВОГО_VPS` укажите публичный IPv4 вашего VPS.
Признак успешной установки — **`VPN_STACK_INSTALL_OK`** в выводе.
Службы и обновления запущены, список устройств пока пуст.

Если установка прервалась, устраните причину и продолжите той же версией
установщика, в том же каталоге и с тем же IP:

```sh
./install.sh --server-ip IP_НОВОГО_VPS --resume
```

[Подробности восстановления](docs/DEPLOYMENT.md#восстановление-прерванной-установки),
[установка без Git и ограничения размещения](docs/DEPLOYMENT.md).

## Создание устройства

На VPS создайте устройство, указав после add его имя. Например:

```sh
vpnctl device add phone
```

Здесь phone — выбранное имя устройства, используемое в названиях phone-smart.json и phone-full.json.

## Перенос и импорт профилей

Для устройства `phone` при установке в `/root/vpn-tunnel` созданы два файла:

- `/root/vpn-tunnel/profiles/phone-smart.json` — **SMART**: домены PROXY и IP из
  клиентских правил идут через VPS, остальное — напрямую, с учётом личного DIRECT.
- `/root/vpn-tunnel/profiles/phone-full.json` — **FULL**: весь разрешённый IPv4
  идёт через VPS. Личный DIRECT влияет на серверную обработку доменов,
  трафик остаётся в туннеле.

Перенесите оба файла на устройство удобным способом и импортируйте их в клиент.
**Профили содержат данные доступа к VPN: храните их приватно и не публикуйте.**

## Проверка подключения

Включите профиль **FULL** и режим **TUN/VPN**, затем откройте
<https://api.ipify.org>. Ожидается публичный IP вашего VPS.
После этого включите SMART и проверьте нужный сервис. Обычные сайты в SMART
могут показывать IP провайдера; `api.ipify.org` по умолчанию идёт через VPS.

## Управление устройствами

```sh
vpnctl device add laptop
vpnctl device list
vpnctl device export phone
vpnctl device revoke phone
```

Каждое добавление выдаёт отдельный UUID и универсальную пару SMART/FULL.
Имя не определяет платформу; выбор ОС не требуется. `list` показывает только
имена пользовательских устройств.

`export` выводит пути и восстанавливает отсутствующие JSON с прежним UUID;
изменённые вручную JSON не перезаписываются. `revoke` отзывает доступ и
локально проверяет отказ. Добавление и отзыв перезапускают Xray, соединения
могут переподключиться. [Подробности операций и восстановления](docs/DEPLOYMENT.md#обслуживание-устройств).

## Личные правила

Установщик создаёт четыре файла с русскими инструкциями и закомментированными
примерами. Примеры не включают правил. Для установки в `/root/vpn-tunnel`:

| Файл | Назначение |
| --- | --- |
| `/root/vpn-tunnel/config/proxy.txt` | Домены через VPS |
| `/root/vpn-tunnel/config/proxy-ip.txt` | Публичные IPv4/CIDR через VPS |
| `/root/vpn-tunnel/config/direct.txt` | Личный DIRECT для доменов |
| `/root/vpn-tunnel/config/ads-exceptions.txt` | Исключения из блокировки рекламы |

Редактируйте файлы вручную или используйте команды:

```sh
vpnctl rule add proxy example.org
vpnctl rule add proxy-ip 8.8.8.8
vpnctl rule add direct example.org
vpnctl rule add ads-exceptions ads.example.org
vpnctl rule remove proxy example.org
```

Удаление любого типа — `remove` вместо `add`. Домены: одна запись на строку,
без схемы, порта и пути; запись охватывает домен и поддомены. Комментарии
начинаются с `#`. IP: публичные IPv4 или CIDR с маской `/12`–`/32`, без битов
хоста. IPv6, приватные, служебные и multicast-адреса не поддерживаются.
[Точные ограничения и лимиты](docs/DEPLOYMENT.md#правила-и-лимиты) также приведены внутри файлов.

Правки применяются после трёх секунд покоя; при занятости повтор — через
15 секунд. Ошибка сохраняет последнюю рабочую политику. Профили пересоздавать
не требуется. Доменные изменения действуют для новых DNS-запросов.

Приоритет на сервере: реклама с учётом исключений → личный DIRECT → личный
PROXY → автоматический DIRECT → автоматический PROXY → обычный DIRECT.
Исключение рекламы снимает блокировку, но само не выбирает маршрут.

В SMART адреса PROXY, полученные через DNS профиля, идут через VPS; затем
учитываются личный доменный DIRECT и клиентские IP-правила. DIRECT не
переопределяет произвольное соединение непосредственно по IP. Автоматический
доменный DIRECT не отменяет клиентский IP-PROXY. В FULL DIRECT не выводит
трафик из туннеля.

## Обновления и обслуживание

Серверные доменные списки обновляются ежедневно около 03:00 UTC,
IP-источники — около 03:20 UTC, с разбросом до десяти минут. Используются
Telegram, Discord, WhatsApp и Cloudflare, включая официальный список Telegram.
При ошибке сохраняется последняя проверенная версия.
SMART получает IP-правила **раз в час**, личный DIRECT — **раз в пять минут**.
FULL эти списки не загружает.

```sh
vpnctl status
vpnctl cleanup
```

`status` проверяет локальные службы, обновления, последнюю политику,
неприменённые правки и целостность Xray по `config/devices.json`. При
локальной неисправности возвращает ненулевой код. Подключение физического
устройства и публичную доступность проверяйте отдельно.

`cleanup` удаляет остатки обновлений, сохраняя активные данные и данные
восстановления. Не удаляйте рабочие данные вручную и не перемещайте
установленный проект.

IPv6 отклоняется; приватные и служебные назначения через VPS заблокированы,
кроме штатных адресов DNS и HTTP правил. Сторонние VLESS-профили с доменным
назначением не поддерживаются. DoH браузера и Private DNS ОС могут обходить
DNS профиля и доменные правила. Для SMART используйте DNS VPN-профиля;
FULL сохраняет отправку разрешённого IPv4 через VPS и при стороннем DNS.
