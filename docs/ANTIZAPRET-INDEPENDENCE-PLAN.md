# План отказа от зависимости от AntiZapret-VPN

Дата: 14 октября 2026 года.
Статус: задача 1 выполнена; реализация задачи 2 ещё не начата.

## Цель и выбранный подход

Убрать обращения к репозиторию `GubernievS/AntiZapret-VPN` при установке,
обновлении кода и обновлении правил VPN.

Дополнительные домены PROXY/DIRECT, рекламные блокировки и исключения,
IP Discord и WhatsApp хранить в нашем репозитории. Включать эти списки
в автономный `install-vpn.py` и доставлять их изменения через `upgrade`.
Хранить их отдельно от личных файлов `config/*.txt`, которые обновление
не должно перезаписывать.

IP Telegram и Cloudflare получать напрямую из официальных источников.
Дополнительные диапазоны из прежних списков сначала проверить и при
необходимости сохранить у себя, чтобы не потерять нужное покрытие.

Остальные внешние источники сохраняются: rulist, antifilter, OISD, AdGuard,
официальные Telegram и Cloudflare. Полностью автономный сбор всех данных
не входит в задачу.

## Основание решения

На момент составления плана код ежедневно скачивал версии списков из AntiZapret-VPN; это
не означает, что автор ежедневно меняет их содержимое. Проверка истории
показала редкие изменения IP-списков. Для Discord обнаружены признаки
ручного сопровождения; автоматический генератор в публичном репозитории
не найден. Дополнительный доменный список при этом меняется часто.

После отвязки новые исправления автора AntiZapret-VPN автоматически
приходить не будут. Сопровождение собственных дополнений станет нашей
ответственностью.

## Задача 1. Зафиксировать состав и содержимое списков

- [x] Выбрать конкретный коммит AntiZapret-VPN как исходную версию данных.
- [x] Подготовить собственные доменные и рекламные дополнения,
  списки IP Discord и WhatsApp; записать происхождение данных.
- [x] Сравнить IP Telegram и Cloudflare с официальными источниками.
- [x] Для различающихся диапазонов зафиксировать решение: сохранить
  у себя либо исключить с обоснованием.

**Критерий готовности:** состав переносимых данных и принимаемые различия
зафиксированы. Работающий код ещё не меняется.

## Задача 2. Перевести доменные и рекламные дополнения на локальные списки

- [ ] Включить собственные списки в автономный установщик и установленный
  комплект проекта, отдельно от личных настроек пользователя.
- [ ] Подключить их к сборке доменной и рекламной политики вместо загрузки
  из AntiZapret-VPN.
- [ ] Адаптировать проверки размеров и изменений списков, привязанные
  к прежним источникам, сохранив проверку политики перед применением.
- [ ] Проверить приоритеты правил, рекламные исключения и сохранение
  рабочей политики при ошибке; добавить необходимые тесты.

**Критерий готовности:** доменная и рекламная политика собирается без
обращения к AntiZapret-VPN; относящиеся к изменению тесты проходят.
Зависимость IP-списков на этом этапе ещё сохраняется.

## Задача 3. Отвязать IP-списки

- [ ] Подключить официальные источники Telegram и Cloudflare напрямую.
- [ ] Использовать собственные списки Discord и WhatsApp и дополнительные

- [ ] Адаптировать проверки источников и изменения покрытия, сохранив
  ограничения клиентских IP-правил.
- [ ] Проверить обновление и сохранение последней рабочей политики
  при недоступности источника или некорректных данных.
- [ ] Проверить отсутствие обращений к AntiZapret-VPN в действующем коде

**Критерий готовности:** действующий код вообще не обращается к AntiZapret-VPN;
тесты загрузки, проверки и применения IP-списков проходят.

- [ ] Проверить SMART/FULL, рекламные исключения и реальные звонки

- [ ] Обновить описание источников и порядок сопровождения собственных

**Критерий готовности:** независимость от AntiZapret-VPN подтверждена
проверками, документация соответствует коду, ограничения записаны.

## Границы и порядок работы

- Выполнять задачи последовательно; каждая задача — отдельный коммит
  и относящиеся к ней проверки. Не откладывать все тесты до задачи 4.
- Не включать общий рефакторинг загрузчиков, автоматический поиск IP
  Discord или переработку README целиком.
- Исторические отчёты и точные тестовые снимки с упоминаниями AntiZapret
  сохранять: они не создают сетевой зависимости.
- Не добавлять инструкции по входу на сервер и скачиванию профилей:
  это остаётся на пользователе.
- При первоначальном сохранении этого плана код и существующая документация
  не менялись. Задача 1 затем выполнена по отдельному запросу.
