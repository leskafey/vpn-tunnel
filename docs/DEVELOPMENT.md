# Разработка и проверки

Основной сценарий установки и подключения — в [README](../README.md),
справочник по обслуживанию — в [DEPLOYMENT](DEPLOYMENT.md).

## Локальные проверки кода

В корне репозитория, на компьютере разработчика:

```sh
./scripts/build.sh
./scripts/test.sh
```

`build.sh` собирает `install-vpn.py` из `src/`. Если нужно только проверить
соответствие установщика исходникам без перезаписи файла:

```sh
./scripts/build.sh --check
```

`test.sh` проверяет синтаксис shell-скриптов, соответствие установщика
исходникам и запускает Python unit-тесты. Тесты используют временные каталоги
и локальный HTTP-сервер; системные команды, службы и VPN-бинарники заменены
заглушками. Локальные HTTP/Unix-сокеты настоящие. Эти проверки не подтверждают
работу systemd, нативных VPN-бинарников или подключение физического устройства.

## Нативные сценарии Linux

Сценарии `tests/check-*-linux.py` предназначены только для одноразовых
Ubuntu-контейнеров. Они не подключаются к рабочему VPS, но могут создавать
службы, менять сеть и выполнять тестовую установку внутри контейнера.
Не запускайте их на рабочем сервере. Нужны окружение, бинарники и файлы,
указанные в каждом сценарии; команды ниже предполагают, что они подготовлены.

| Сценарий | Что проверяет и ограничения |
| --- | --- |
| [check-install-paths-linux.py](../tests/check-install-paths-linux.py) | Настоящий systemd: разбор юнитов, рабочий каталог, аргументы, переменные окружения, ограничения записи, watcher, CLI и эксклюзивную публикацию состояния Linux, включая `/root/vpn-tunnel` и нестандартные пути. Использует диагностические программы; VPN и установку не запускает. |
| [check-review-linux.py](../tests/check-review-linux.py) | Нативные конфигурации SMART/FULL, запрещённые назначения, локальный VLESS, DNS TCP/UDP, HTTP, fake-IP, отзыв устройства и изолированную проверку политики. Транспорт запускается напрямую, без systemd; источники — локальные тестовые данные. |
| [check-root-access-linux.py](../tests/check-root-access-linux.py) | Настоящий Mihomo 1.19.31 и HTTP-службу под systemd при исходных правах `/root` и проекта `0700`: чтение нужных данных, запрет чтения ключей/профилей/личных правил и записи в политики, DNS TCP/UDP, смену поколений и атомарную замену конфигурации. Проверяет повторную подготовку каталогов; полный установщик не запускает. |
| [check-vpn-installer-linux.py](../tests/check-vpn-installer-linux.py) | Тестовую установку и управление устройствами под systemd с синтетическим локальным VLESS-адресом. Публичный вход на VPS не проверяет; использует внешние источники и проверки HTTPS, локальный STUN. |
| [check-vpn-small-providers-linux.py](../tests/check-vpn-small-providers-linux.py) | Первую загрузку клиентских JSON с пустым кэшем и ответы HTTP 200/HEAD/304 через локальный VLESS в подготовленной контейнерной установке. TUN и физическое устройство не проверяет. |

В подготовленном контейнере с репозиторием в `/repo`:

```sh
python3 /repo/tests/check-install-paths-linux.py
python3 /repo/tests/check-review-linux.py --long-project-root
python3 /repo/tests/check-root-access-linux.py
```

Вариант `--long-project-root` дополнительно проверяет сокет изолированной
политики при корне `/srv/deployments/vpn-projects/vpn-tunel`.

Для `check-root-access-linux.py` нужны закреплённые ARM64-бинарники в
`/native-binaries` и их SHA-256 в `/native-checksums.json`. Сценарий требует
настоящий systemd 255 в Ubuntu 24.04-контейнере и уже закрытый `/root`; он не
меняет права `/root` и не подтверждает работу на amd64 VPS, полную установку,
продолжение полного установщика, публичный вход или физические клиенты.
Отчёт записывается внутри контейнера в `/tmp/root-access-results.json`.

Локальный [test_root_access.py](../tests/test_root_access.py) проверяет модель
доступа, отсутствие изменений прав при аудите, прерывание подготовки каталогов
и `--resume` с сохранением ключей и личных правил. Права владельцев и системные
вызовы в нём заменены заглушками; подтверждение реального доступа даёт только
отдельный контейнерный сценарий.

Локальный [test_confirmed_defects.py](../tests/test_confirmed_defects.py)
проверяет значения сгенерированных путей, CLI из другого каталога, прерывания
начальной инициализации, отказ чужому состоянию, сохранение идентичности без
журнала, длину и очистку проверочного сокета. Системные команды и бинарники
в этих тестах заменены заглушками.

## Исторические отчёты

Файлы в `verification/` описывают конкретные проверки, окружения и SHA-256.
Они не подтверждают текущую версию: для неё проверки нужно выполнить отдельно.
Пути и результаты в исторических отчётах сохранены; примеры прежнего размещения
не являются рекомендациями по установке текущей версии.
В таблице приведены начала SHA-256 установщика; полные значения находятся
в самих отчётах.

| Отчёт | Проверенная версия и область проверки |
| --- | --- |
| [installer-linux-acceptance.json](../verification/installer-linux-acceptance.json) | SHA-256 `8d54c2f68685…`: Ubuntu 24.04 amd64 в эмуляции, изолированный Docker/systemd, установка и локальный VLESS. Физические amd64-ресурсы, публичный вход и внешний UDP STUN не проверялись. |
| [installer-small-providers-acceptance.json](../verification/installer-small-providers-acceptance.json) | 2026-10-11, SHA-256 `8d54c2f68685…`: начальная загрузка удалённых JSON и HTTP через локальный VLESS. Без TUN и физического устройства. |
| [review-linux-regressions.json](../verification/review-linux-regressions.json) | SHA-256 `07d8cbf44909…`: отдельные нативные проверки на Ubuntu 24.04 ARM64 в Docker. Без полной установки и systemd. |
| [project-layout-local-checks.json](../verification/project-layout-local-checks.json) | 2026-10-12, SHA-256 `4e80dea6a67b…`: 98 локальных тестов на Darwin, сборка и проверки структуры проекта. Нативные бинарники и systemd не запускались. |

Нативные результаты вынесены в два отчёта ниже. |
| [confirmed-defects-systemd-paths.json](../verification/confirmed-defects-systemd-paths.json) | SHA-256 `695e6e752d39…`: systemd 255 в одноразовом Ubuntu 24.04-контейнере, разбор путей и ограничения записи. Программы диагностические; без VPN-бинарников и полной установки. |

[helper-baseline.json](../verification/helper-baseline.json) содержит SHA-256
отдельных вспомогательных исходников от 2026-10-11, а не результат полной
установки. Не используйте его как подтверждение работоспособности проекта.

Исторические результаты не охватывают полный сценарий на отдельном чистом
Ubuntu 24.04 amd64 VPS со всеми источниками под systemd: прерывание и
продолжение установки, перезагрузку, публичный вход, физические SMART/FULL
клиенты, ежедневные обновления с ограничениями ресурсов и наблюдение
клиентских интервалов 1 час/5 минут. Рабочий VPS в перечисленных проверках
не использовался.
